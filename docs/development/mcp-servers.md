# MCP Servers for AI-Assisted Development

This document describes the Model Context Protocol (MCP) servers configured for
OpenCode in this repository, how to (re)install them, their security posture,
and how they were validated.

Audit/initial setup: 2026-11-16, OpenCode v2.2.5.

## Configuration locations (two-tier model)

- **Committed base — `opencode.json` (repo root)**: every secret-free server:
  the four GitMCP doc servers, `orm-lens`, `playwright`, and a *disabled*
  `postgres` stub that reads `{env:MRMAP_MCP_DATABASE_URL}`. Because it is a
  tracked file, **every clone, worktree and host gets these servers
  automatically** — including AO agents working in worktrees.
- **Local per-host override — `.opencode/opencode.json`**: generated by
  `scripts/mcp-setup.sh`, mode 600, matched by the committed `.gitignore`
  (`/.opencode/`). Currently only the enabled `postgres` entry with the
  dev-only read-only DSN. OpenCode merges it over the base and a same-named
  server entry is *replaced wholesale* by the local one — that is how the
  stub gets enabled. Never put credentials into `opencode.json`.
- **Global**: `~/.config/opencode/opencode.jsonc` → `mcp.servers.playwright`
  (backup `…bak-20261116`). Optional convenience for sessions *outside* the
  repo; inside the repo the project entry wins (same name → no duplicate).
- `/etc/opencode/opencode.jsonc` is OTA-managed (provides the `gedaechtnis`
  memory MCP) — do not edit; OTA rewrites it.
- Cline/Agent-Orchestrator settings (`~/.cline/...cline_mcp_settings.json`)
  were left untouched (empty, as found).

OpenCode merges configs root-down: global `<` repo `opencode.json` `<` repo
`.opencode/opencode.json`. Config changes are hot-reloaded; force with
`/reload` in the TUI. Verify with `/mcps` (authoritative; the CLI
`opencode mcp list` only shows the servers of the *current* directory's
config layers) or the service log
(`grep 'mcp connected' ~/.local/share/opencode/log/opencode.log`).

## Installation / reproduction

**New host / new checkout — one command:**

```bash
cd <checkout> && ./scripts/mcp-setup.sh
```

It installs orm-lens (`orm-lens[mcp]==1.18.0` into `~/.venvs/orm-lens`),
ensures the read-only DB role, (re)starts the loopback forwarder for the
slot's postgis container (from `.env`: `COMPOSE_PROJECT_NAME`, `DB_USER`,
`DB_NAME`) and writes the local override. Idempotent; options:
`MRMAP_MCP_NO_DB=1` (host without the dev stack), `MRMAP_MCP_PORT=NNN`
(forwarder port). Requirements: `python3`, Docker + running slot stack for
the postgres part; Node >= 18 for `playwright`/`postgres` (npx). The doc
servers and `orm-lens` work without any of that except python3/venv.

<details>
<summary>What the script does, step by step (manual reproduction)</summary>

```bash
# 1. Docs servers: nothing to install (hosted GitMCP endpoints, version-
#    pinned URLs — see opencode.json).

# 2. ORM Lens (isolated venv; static analyzer, does not touch the repo venv)
python3 -m venv ~/.venvs/orm-lens
~/.venvs/orm-lens/bin/pip install "orm-lens[mcp]==1.18.0"

# 3. Playwright MCP + Postgres MCP need no install: `npx -y <pkg>@<pinned>`
#    fetches on first use. Node.js >= 18 required (nvm node 22.23.3 here).
#    Playwright uses the cached Chromium in ~/.cache/ms-playwright
#    (chromium-1254); refresh with:
npx -y @playwright/mcp@0.0.85 --version   # probe only

# 4. Dev PostgreSQL access (read-only role + loopback proxy)
set -a; . ./.env; set +a
RO_PW=$(openssl rand -hex 16); echo "$RO_PW" > ~/.mrmap_mcp_ro_pw; chmod 600 ~/.mrmap_mcp_ro_pw
docker exec -i -e RO_PW="$RO_PW" mrmap-postgis-1 psql -v ON_ERROR_STOP=1 -v ro_pw="$RO_PW" \
  -U "$DB_USER" -d "$DB_NAME" <<'SQL'
DO $$ BEGIN
  IF NOT EXISTS (SELECT FROM pg_roles WHERE rolname='mcp_readonly') THEN
    CREATE ROLE mcp_readonly LOGIN;
  END IF;
END $$;
ALTER ROLE mcp_readonly PASSWORD :'ro_pw';
ALTER ROLE mcp_readonly SET statement_timeout = '30s';
ALTER ROLE mcp_readonly SET idle_in_transaction_session_timeout = '30s';
GRANT pg_read_all_data TO mcp_readonly;
GRANT CONNECT ON DATABASE mrmap TO mcp_readonly;
SQL

# Postgres is not published on a host port by docker-compose.yml; a small
# loopback-only TCP forwarder bridges host:127.0.0.1:15432 -> postgis:5432:
docker rm -f mrmap-mcp-dbproxy 2>/dev/null
docker run -d --name mrmap-mcp-dbproxy --network mrmap_mrmap-internal \
  -p 127.0.0.1:15432:5432 --restart unless-stopped --read-only --memory 64m \
  node:26-alpine node -e '
const net=require("net");
const srv=net.createServer(c=>{const up=net.connect(5432,"postgis");
  c.pipe(up); up.pipe(c);
  c.on("error",()=>up.destroy()); up.on("error",()=>c.destroy());});
srv.listen(5432,"0.0.0.0");'

# 5. The local override .opencode/opencode.json (postgres enabled with
#    DATABASE_URL=postgresql://mcp_readonly:<RO_PW>@127.0.0.1:15432/mrmap,
#    mode 600) is generated by scripts/mcp-setup.sh; .gitignore keeps it out
#    of git on every host.
```
</details>

For git **worktrees** (mrp slots): `opencode.json` is a tracked file, so every
worktree automatically gets the doc servers, `orm-lens` (resolves its own
tree from the session cwd) and `playwright` — nothing to copy. Only the
`postgres` override is per-checkout, because each slot has its own database:
run `./scripts/mcp-setup.sh` inside the worktree (it reads that slot's `.env`)
or skip it, or use `MRMAP_MCP_PORT` if the 15432 forwarder is already taken
by slot 0 (one forwarder can only serve one DB).

## Startup / shutdown behavior

- OpenCode starts local stdio servers lazily on first connection per project
  directory and closes them when the OpenCode service shuts down. No
  permanently running MCP processes are started by us.
- `playwright` launches headless Chromium only while a browser tool is in
  use; `--isolated` means a fresh profile per session; the browser closes
  with `browser_close` or after the idle timeout (1 h by default for
  headless).
- `postgres` and `orm-lens` are single stdio processes started by OpenCode;
  `postgres` connects to the DB per tool call.
- The only always-running component is the loopback DB forwarder container
  `mrmap-mcp-dbproxy` (node, ~64 MB limit, restartable by docker). Remove it
  with `docker rm -f mrmap-mcp-dbproxy` when the postgres MCP is not needed;
  the MCP server then simply fails its connection until the proxy is back.
- The four GitMCP servers are remote endpoints: nothing to start locally;
  each OpenCode directory keeps one HTTPS connection.

## Security posture

- **Postgres**: dev DB only. The `mcp_readonly` role is enforced *at the
  database level*: `pg_read_all_data` + no schema/table write grants
  (verified: `CREATE TABLE` → `permission denied for schema public`),
  30 s `statement_timeout` (also caps `EXPLAIN ANALYZE` damage), and the
  server runs without `ALLOW_WRITES`, so `pg_query` uses `BEGIN READ ONLY` +
  single-statement extended protocol. The DSN is in a 600-mode file that is
  `.git/info/exclude`d; the proxy binds **127.0.0.1 only**. Never put
  production credentials into these files.
- **Playwright MCP** is explicitly "not a security barrier": we run it
  `--headless --isolated`, keep its default file-access restriction (workspace
  roots only), and its output files (`.playwright-mcp/`, screenshots) land in
  the workspace — clean them up (they are untracked repo noise).
- **GitMCP (gitmcp.io)** is a GitLab-operated hosted service. It indexes the
  *public* pinned repo tag only; no local code, no credentials, no secrets
  leave the machine except your search queries. Read-only tools.
- **orm-lens** is static, read-only, sandboxable (`ORM_LENS_ALLOWED_ROOTS` is
  set to `/home/ota/git/mrmap`), zero runtime deps. Third-party single-
  maintainer project (MIT, on the MCP registry) — pinned to 1.18.0.
- All Node servers are pinned to exact npm versions (no floating `@latest`);
  packages are from official publishers (`microsoft-oss-releases`,
  `@mui` team, `yawlabs`). npx caches packages per version.
- Python servers are pinned inside an isolated venv (`~/.venvs/orm-lens`);
  the repo's `.venv` is untouched.

## Agent assignment (recommended)

OpenCode exposes each server's tools as `<server>_<tool>`; grant per-agent by
permission patterns (see "Suggested assignment" below). This also works for
Cline/AO via its own MCP settings file if you choose to mirror the entries
(not done in this audit — AO config was left as-is).

| Agent / task | Servers | Permission pattern |
|--------------|---------|--------------------|
| Backend development | django-docs, orm-lens | `django_docs_*`, `orm_lens_*` allow |
| Frontend development | react-admin-docs, mui-docs, mui-x-docs | `react_admin_docs_*`, `mui_docs_*`, `mui_x_docs_*` |
| ORM performance | orm-lens, postgres | `orm_lens_*`, `postgres_*` (never set `ALLOW_WRITES`) |
| UI testing | playwright | `playwright_*` |
| Integration testing | django-docs, react-admin-docs, playwright | combined allow |

Example (add under an entry in `agents` in the respective config):

```jsonc
"agents": {
  "frontend": {
    "permission": [
      { "action": "*", "resource": "*", "effect": "allow" },
      { "action": "postgres_*", "resource": "*", "effect": "deny" },
      { "action": "playwright_*", "resource": "*", "effect": "deny" }
    ]
  }
}
```

(No second orchestration layer was introduced; AO/Cline configs untouched.)

## Troubleshooting

- **Server missing from `opencode mcp list` inside the repo**: the CLI may
  not show project-scope servers in every invocation — the authoritative
  source is the service log: `grep 'mcp connected' ~/.local/share/opencode/log/opencode.log`;
  in the TUI use `/mcps`, or `/reload` after config edits.
- **postgres "connection refused 127.0.0.1:15432"**: the stack or the
  forwarder is down. Start DB: `mrp up postgis` (or `docker start
  mrmap-postgis-1`); forwarder: `docker start mrmap-mcp-dbproxy` (or the
  docker run command above). Verify: `ss -tln | grep 15432`.
- **postgres "password authentication failed for mcp_readonly"**: the role
  password in `.opencode/opencode.json` must match `~/.mrmap_mcp_ro_pw`;
  recreate via the SQL above and update both.
- **gitmcp timeout / 4xx / ECONNRESET**: GitMCP is a free hosted service; the
  server log occasionally shows `ECONNRESET` / rejected concurrent calls
  (observed during this audit when 4 queries ran concurrently, sequential
  retry succeeded) — call GitMCP tools sequentially rather than in parallel
  bursts, and simply retry. Health check:
  `curl -s https://gitmcp.io/<owner>/<repo>/mcp`. Version URLs
  (`.../<repo>/<tag>/mcp`) pin docs to the installed version; if a tag is
  removed upstream, the endpoint 404s — bump the pin.
- **playwright browser not found**: `npx -y playwright@<bundled> install
  chromium` or use system Chrome via `--browser chrome` (chrome binary
  exists here). `--isolated` prevents profile locks between parallel agents.
- **npx cold start > startup timeout**: pins are cached after first run;
  global `mcp.timeout.startup` is raised to 90 s. Check `~/.npm/_npx`.
- **Proxy**: this environment uses no HTTP(S) proxy (`NO_PROXY` set for
  docker-internal hosts only). If a corporate proxy is enabled later, pass it
  to Playwright via `--proxy-server` and ensure npm/GitMCP TLS goes through it.
- **Repo pollution from playwright**: delete `.playwright-mcp/` and stray
  `*.png` in the workspace root after sessions (untracked; never commit).
